# 河道排污检测系统设计文档

- 日期：2026-10-28
- 状态：待评审

## 1. 背景与目标

利用现有河道球机监控视频，自动识别排口污水排放事件并告警。

**排污的视觉特征（来自现场观察）：**
1. 污水排出导致排口附近水面流动变化/波动明显大于正常河面
2. 污水颜色比正常河水更黑（黑臭水体）

**主要干扰：**
- 光线变化、阴影（也会造成局部变暗）
- 船只、漂浮物、岸线/桥墩等非水面物体

**约束条件：**
- 部署机器为纯 CPU（性能较强），无 GPU
- 无法实时分析视频流，通过海康 Artemis 平台 `manualCapture` 接口每 5 分钟抓图分析
- 摄像头为球机，大部分视角固定，但会被现场人员偶尔转动，且无法人工配合恢复/重新标定
- 排污事件一般持续较长时间（支持延迟确认策略）

**已有资源：**
- 海康 Artemis 平台 API：抓图（manualCapture）、录像回放（playbackURLs）。无云台控制权限
- 已训练好的 YOLO 水面分割模型（输出分割 mask）
- 公司内网部署的多模态大模型，OpenAI 兼容接口
- 用户自有告警推送渠道（本系统只提供告警事件接口）
- 13 个示例视频（`videos/`），用于离线验证与阈值调优

## 2. 总体架构

三级漏斗判定结构：越贵的判据越靠后，调用频率越低。

```
调度器：每5分钟触发一次采样任务（每摄像头独立）
        ↓
采样器：manualCapture 连续抓 5 帧（间隔约2秒）
        ↓
YOLO 水面分割（已有模型，CPU 推理，每次采样跑）
        ↓
视角配准：SIFT/ORB 特征点 + 单应矩阵，映射排口点坐标
        ↓
基于水面 mask 重建三个 ROI（排口区/扩散区/参考区）
        ↓
① 规则引擎：三特征加权打分（仅在水面像素上计算）
   score < 0.4 → 正常，存档结束
   score > 0.7 → 疑似
   0.4~0.7（灰色地带）→ ②
        ↓
② CNN 分类器（MobileNetV3-Small 二分类，ONNX CPU）
   判正常 → 存档结束；判疑似 → ③
   ※冷启动期无训练数据时此层关闭，灰色地带直接进 ③
        ↓
③ VLM 终判（公司内网多模态大模型，OpenAI 兼容接口）
   输入：当前帧(标注ROI) + 历史正常参考帧 + 上一采样帧 + 特征数值
   输出：结构化 JSON 判定
        ↓
时序状态机：滑动窗口连续 3 次疑似（约15分钟）→ 确认排污
        ↓
告警事件 → alert(event) 接口 → 用户对接自有推送渠道
        ↓
存档：SQLite（特征值/判定记录）+ 文件（截图归档）
```

**关键设计洞察：** 5 分钟一帧不等于只有孤立单帧。每次采样点用 `manualCapture` 连续抓 5 帧（间隔几秒），即可用帧间差分计算"波动"这一动态特征——这是区分排污与阴影的最有力特征（阴影静止，污水流动）。

## 3. YOLO 水面分割的三个作用

### 3.1 简化标定
人工只需在画面上**点出排口位置**（一个点），YOLO 生成水面 mask 后自动生成三个 ROI：
- **排口区**：排口点周围的水面像素块
- **扩散区**：排口点下游方向的水面带
- **参考区**：水面 mask 中远离排口的区域（同画面内的正常水面）

系统生成后展示供人工确认/微调，存入摄像头配置 JSON。

### 3.2 特征计算约束在水面像素上
每次采样先跑 YOLO 分割，三个 ROI 与水面 mask 取交集后再计算特征——岸线、桥墩、船只、漂浮垃圾等误报源在进入规则引擎前被排除。若排口区水面覆盖率过低（大量漂浮物遮挡），主动降低本次判定置信度。

### 3.3 视角变化后的 ROI 自动重建
- 配准成功：单应矩阵只需映射**排口一个点**，水面区域用新画面的 YOLO 分割结果重新生成
- 配准失败但画面有足够水面：调 VLM 定位排口点 → 重建 ROI → 自动恢复监测（一期即实现，无需人工）

## 4. 规则引擎（特征设计）

三特征加权打分，`score ∈ [0,1]`。所有特征仅在水面像素上计算。

| 特征 | 计算方式 | 抗阴影原理 |
|---|---|---|
| 相对黑度 | 排口区 Lab-L 均值 ÷ 参考区 L 均值（同图内比值） | 整体光照变化时分子分母同比例变化，比值稳定；阴影是局部的，不会让排口区相对参考区**持续**变暗 |
| 波动能量 | 5 帧连续帧差在排口区的能量均值 ÷ 参考区帧差能量 | 阴影静止、帧差≈0；污水排放有持续湍流扩散 |
| 颜色偏离 | 排口区 HSV 色调/饱和度与参考区的差异 | 黑臭水体色度特征与正常河水可区分 |

**辅助弱特征：历史同时刻基线**——排口区黑度与该摄像头近 7 天同一时刻黑度中位数对比，进一步压制光照误报。

**双阈值：** `score < 0.4` 正常；`> 0.7` 疑似；中间进 CNN。阈值初值通过离线回放 videos/ 样本调优确定，上线后根据存档数据持续调整。

## 5. CNN 分类器

- MobileNetV3-Small 二分类（排污/正常），输入为排口区+扩散区裁剪图，ONNX Runtime CPU 推理（每张图几十 ms）
- **冷启动策略：** 初期无训练数据时 CNN 层关闭，灰色地带直接送 VLM；运行中自动把 VLM 判定过的样本存为训练集，积累几百张后训练第一版
- 随 CNN 上线并逐步迭代，VLM 调用量持续下降——系统越用越便宜、越用越快

## 6. VLM 终判

- 公司内网多模态大模型，OpenAI 兼容接口（`openai` SDK 改 `base_url` 接入）
- 输入 3 张图：当前帧（标注 ROI）、该摄像头历史正常参考帧、上一采样点帧；外加规则引擎输出的特征数值
- 要求返回严格 JSON：

```json
{
  "is_discharge": true,
  "confidence": 0.85,
  "reason": "排口区水体明显深于参考区且呈扩散态势",
  "shadow_suspect": false
}
```

- `shadow_suspect` 字段让模型专门评估当前画面是否存在阴影干扰，双重保险
- `reason` 直接写入告警消息，人工复核友好
- VLM 判定结果与对应截图自动存入标注样本库，供 CNN 训练
- VLM 服务不可用时降级：A+C 独立工作（仅误报增多，不中断监测）

## 7. 时序状态机与告警

每个摄像头独立维护状态机：

```
正常 → 观察（1次疑似）→ 高度观察（连续2次）→ 告警（连续3次，约15分钟）
```

- 中间任何一次采样判正常则降级/复位——瞬时光照干扰、船只经过不会触发告警
- 告警事件内容：`{camera_id, 时间, 当前截图路径, 连续疑似帧路径列表, VLM解释, 特征值快照}`
- 通过 `alert(event)` 接口函数输出，用户在其中对接自有推送渠道
- 告警后进入冷却期（30 分钟），避免同一排污事件重复推送

## 8. 视角变化处理（无云台控制权限、无人工配合）

三层策略：

**第 1 层：自动配准校正**
- 标定时保存参照帧的 SIFT/ORB 特征点集
- 每次采样用特征匹配 + 单应矩阵估算当前画面相对标定画面的几何变换（球机 pan/tilt/zoom 近似满足单应变换）
- 置信度高 → 映射排口点坐标，用 YOLO 新分割结果重建 ROI，判定继续，无需人工

**第 2 层：优雅降级 + 自动恢复**
- 配准失败或排口已不在画面内 → 该摄像头进入"视角异常"状态：照常截图存档但不做判定，发一次通知知会（无需人处理）
- 每次采样持续重试配准；现场人员转回摄像头时自动恢复（残余偏差由第 1 层校正消化）
- 视角异常持续较长时间（如 1 小时）且画面内有足够水面：调 VLM grounding 定位排口点 → 重建 ROI → 自动恢复监测

**第 3 层（预留，当前不可用）：** 采样前转预置位。需云台控制权限，当前无此权限，仅预留接口。

## 9. 存储与运维

- **SQLite：** 每次采样一行记录（时间、camera_id、各特征值、各级判定结果、最终状态、各阶段耗时）——阈值调优与误报排查全靠此表
- **文件归档：** 截图按 `camera_id/日期/` 存放；正常帧保留 7 天滚动删除；疑似/告警帧永久保留（同时是 CNN 训练数据来源）
- **标注样本库：** VLM 判定过的样本单独存放（图片 + JSON 标签）
- **日志：** 分级记录，重点记录各判定层结果与耗时

## 10. 模块划分

| 模块 | 职责 | 依赖 |
|---|---|---|
| `scheduler` | 定时触发各摄像头采样任务 | APScheduler 或简单循环 |
| `sampler` | 调海康 API 连续抓 5 帧 | 用户海康 API 封装 |
| `water_seg` | YOLO 水面分割 | 用户已有模型，ONNX/PT |
| `view_align` | 特征点配准、排口点映射、ROI 重建 | OpenCV |
| `rule_engine` | 三特征提取与打分 | OpenCV/numpy |
| `cnn_classifier` | 二分类推理 | ONNX Runtime |
| `vlm_judge` | 多模态终判 | openai SDK |
| `state_machine` | 时序确认、冷却期管理 | SQLite |
| `alerter` | 告警事件接口（空实现，用户填推送） | — |
| `storage` | SQLite 记录 + 截图归档 | sqlite3 |
| `calibrate_tool` | 标定小工具（点排口→生成 ROI→确认） | OpenCV GUI |
| `replay_tool` | 离线回放器：视频按"每5分钟抽5帧"模拟在线采样 | OpenCV |

## 11. 开发与验证路径

1. **离线回放验证**：用 `replay_tool` 把 videos/ 里 13 个视频按"每 5 分钟抽 5 帧"模拟在线采样，跑通整条管线
2. **阈值调优**：人工标注视频中的排污时段，对比规则引擎输出，确定双阈值与特征权重
3. **在线试运行**：切真实摄像头，只记录不告警，观察 1~2 周误报率，微调阈值
4. **正式告警**：接入推送渠道
5. **CNN 迭代**：样本积累足够后训练 CNN，灰色地带分流，VLM 调用量下降

## 12. 错误处理

| 故障 | 处理 |
|---|---|
| 海康 API 抓图失败 | 重试 2 次，仍失败跳过本次采样并记录；连续多次失败发通知 |
| YOLO 推理失败/无水面 | 跳过本次判定，记录；持续异常发通知 |
| 视角配准失败 | 进入视角异常状态（见第 8 节） |
| VLM 调用失败/超时 | 本次疑似按 A+C 结果处理，标记"未经VLM确认"；连续失败发通知 |
| SQLite 写入失败 | 降级为只写日志文件，发通知 |

## 13. 非目标（本期不做）

- 实时视频流分析
- 云台控制/预置位巡航（无权限，仅预留接口）
- Web 看板（ SQLite + 文件存档已满足回溯需求，看板可作为后续增强）
- 多排口复杂场景（单摄像头单排口起步；多排口通过多配置实例支持）
